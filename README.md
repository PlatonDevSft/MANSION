# Mansion

Русскоязычный фундамент Premium Trading Intelligence Platform. Next.js App Router, React, строгий TypeScript, Tailwind 4, Motion, Embla, Supabase. Шрифты Manrope и Cormorant Garamond с кириллицей поставляются локально.

## Запуск

Node.js 22 или 24, npm. Из корня репозитория:

```sh
npm ci
npm run dev
```

Откройте `http://localhost:3000`. Без переменных окружения включён явно помеченный локальный DEMO. Журнал, заметки, стратегии, публикации и обращения хранятся в localStorage этого браузера и не синхронизируются. В production это тот же ограниченный demo preview; не вводите конфиденциальные данные. Отдельный облачный раздел `/account` всегда требует серверной авторизации.

## Реализовано

- Dashboard: три денежных агрегата пользователя, управляемая карусель семи разделов (стрелки, swipe, клавиатура), 3D-иллюстрации стекла, обсидиана и металла, демо-профили, поддержка.
- `/trading`: локальный CRUD, валидация Zod/React Hook Form, подтверждение удаления, поиск, статус/теги, сортировка, пагинация, экспорт JSON, аналитика, Lightweight Charts, детерминированные инсайты с фильтром подтверждающих сделок.
- `/knowledge`: три редакционных демо-материала, поиск, категории, избранное, CRUD личных заметок.
- `/strategies`: локальное создание/редактирование/удаление правил.
- `/community`: локальные публикации, лайки и комментарии; это не настоящее сетевое сообщество. Демонстрационные профили.
- `/requests`, `/settings`: локальные обращения, профиль, удаление демо-данных.
- `/login`, `/auth/callback`, `/account`: серверный Supabase Auth, регистрация, вход, выход, email recovery и обновление пароля. Облачный CRUD сделок через временный JSON-редактор, с Zod на сервере и RLS. Не смешивается с локальным демо.

## Ограничения первой итерации

Этапы A/B и основная часть C. Облачную авторизацию и RLS нужно интеграционно проверить на реальном проекте Supabase. Удобная форма демо-журнала ещё не подключена к облачному адаптеру; облачный журнал доступен отдельно через технический JSON-редактор. История браузера не переносится в облако автоматически.

Ещё не реализованы: прикрепление скриншотов в UI, полноценная многофакторная аналитика/серии/группировки, социальные подписки/модерация/публикация сделок, облачные настройки/заметки/стратегии, служба ответов поддержки, удаление облачного аккаунта. Структуры таблиц и приватного Storage подготовлены. Публичные профили пока демонстрационные, журнал приватен.

AI, новости, экономические данные, биллинг, копирование ордеров и бэктестинг **не подключены**. Разделы показывают честные состояния недоступности, интерфейсы провайдеров находятся в `src/lib/providers.ts`. Автоисполнение ордеров отсутствует. Тексты интерфейса русские; полноценное выделение словарей RU/EN — следующий этап.

## Финансовая модель

Только Spot Long и линейные USD-контракты. Размер позиции — количество базового актива. Числа передаются строками, Zod ограничивает точность, Decimal.js считает `(exit − entry) × quantity × direction − fees − funding`. Funding пока только уплаченный расход. Инверсные контракты, опционы, Forex lots, мультивалютная агрегация и полученный funding не поддерживаются.

Метрики используют только закрытые сделки. Месяц — календарный UTC. Средний результат — арифметический средний net P&L в USD, а не процент доходности. Profit Factor при нулевом gross loss отображается как неопределённый. График — накопленный реализованный P&L, не equity curve. Демо-сделки фиксированы в октябре 2026: месячный результат в других месяцах закономерно равен нулю. Доходности профилей условны и не верифицированы.

## Supabase

1. Создайте проект Supabase.
2. Примените `supabase/migrations/0001_foundation.sql` в SQL Editor либо через CLI (`supabase link`, затем `supabase db push`). Не применяйте повторно тот же SQL вручную.
3. Скопируйте `.env.example` в `.env.local` и задайте `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` (публичный anon key) и `NEXT_PUBLIC_SITE_URL`.
4. В Supabase Auth настройте Site URL и redirect URL: `http://localhost:3000/auth/callback`, production `https://ваш-домен/auth/callback`, а также recovery URL с `?recovery=1`. Добавляйте только доверенные preview-домены.
5. Перезапустите Next.js, зарегистрируйтесь в `/login`, подтвердите email. `/account` доступен только после `auth.getUser()`.
6. Создайте сделку, выйдите и войдите другим пользователем: приватные данные не должны читаться/меняться. План ручной проверки — `docs/security-validation.md`.

**Не используйте service_role в клиенте.** Приложению он не требуется. Приватный bucket `trade-images` принимает JPEG/PNG/WebP до 5 MiB с путями `user-id/...`; UI загрузки не реализован. Миграция не публикует изображения. Облачные операции дополнительно ограничены RLS.

## GitHub и Vercel

Код подготовлен в ветке `feat/mansion-foundation`. Для пустого репозитория:

```sh
git add .
git commit -m "Build Mansion foundation and demo trading journal"
git push -u origin feat/mansion-foundation
```

После push откройте PR в GitHub, выполните review и merge. Если `main` ещё не существует, создайте её из первого коммита через согласованный процесс репозитория. Не публикуйте `.env.local`.

Vercel → Add New Project → импорт GitHub-репозитория → Next.js → build `npm run build`. Без Supabase будет ограниченное демо. Для облачной части задайте три переменные из `.env.example` в Production и Preview, настройте redirect URLs в Supabase и выполните redeploy. Ключи AI в этой версии не требуются; будущие AI-вызовы добавляйте только в серверный провайдер с согласием пользователя и проверкой evidence, не в `NEXT_PUBLIC_*`.

Свой домен: Vercel Project → Settings → Domains; внесите DNS-записи, которые укажет Vercel, дождитесь TLS, обновите Site URL и redirect URLs Supabase.

Обновления — через PR и CI. Для отката используйте Vercel deployment rollback. Откат кода не откатывает базу данных: перед будущими миграциями делайте backup и используйте совместимые расширения схемы. Не удаляйте таблицы для исправления деплоя.
